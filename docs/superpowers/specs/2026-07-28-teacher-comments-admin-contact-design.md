# 教师详情、评论展示与管理员联系入口任务设计

## 任务目标

在不改变现有课程定义、登录方式和管理员权限体系的前提下，完成四组相互关联的体验改进：

1. 评论显示评论者当前昵称和简洁时间。
2. 教师目录与课程详情中的教师卡片都可进入统一教师详情页，并在详情页完成教师点赞和评论评价。
3. 个人页恢复管理员联系入口，使用历史版本中的原管理员微信二维码。
4. 追加 2026 秋任课与教材资料：保留所有往期任课教师，课程基本信息只显示最新教材。

本文件是本轮实现的唯一规格。旧的 `2026-07-28-comment-author-time-design.md` 不再单独作为实施依据。

## 已确认的产品规则

### 评论身份与时间

- 课程评论和教师评论都显示评论者当前昵称，不再固定显示“用户”。
- 用户修改昵称后，历史评论在下次刷新时同步显示新昵称。
- 每条评论头部格式为：`昵称　YYYY年M月D日 HH:mm`。
- 示例：`冬日眠　2026年7月28日 12:03`。
- 时间按查看者设备本地时区格式化；时间无效或缺失时不显示时间，不得出现 `Invalid Date`。
- 只公开昵称，不公开真实姓名、学号、账号标识、用户内部 ID 或头像。
- 昵称异常为空时显示“新同学”。

### 评论权限

- 课程评论和教师评论都对所有能打开对应详情页的访问者可见；是否登录、是否点赞只影响发布和删除权限，不影响浏览。
- 课程评论：登录后即可直接评论，不要求先给课程点赞。
- 教师评论：必须登录并先给该教师点赞，之后才能评论。
- 取消教师点赞后，历史评论保留，但不能继续发布教师评论；重新点赞后恢复评论能力。
- 评论长度仍为 1 至 300 个字符。
- 评论删除规则保持不变：作者可删除自己的评论，管理员可删除任意违规评论。

### 教师详情入口

- 教师目录中的整张教师卡片可点击进入教师详情页。
- 课程详情底部的教师卡片也可点击进入同一个教师详情页。
- 两个入口使用教师稳定目录标识 `directoryId`，不得仅用数组下标或展示姓名作为路由标识。现有教师互动 API 中名为 `teacherId` 的路径参数和响应字段实际都传递这个 `directoryId`。
- 卡片上的点赞按钮继续直接点赞或取消点赞，并使用 `catchtap` 或等价方式阻止事件冒泡，不能误触发页面跳转。
- 课程详情中的教师区继续放在课程评论区下面；评论较多时教师区自然下移，不新增吸顶或重排逻辑。

### 任课历史与最新教材

- 任课教师采用追加式历史记录：新学期增加教师和任课学期，不删除、覆盖往期教师。
- 课程详情底部“教师”区显示所有已知教过该课程的教师，而不是只显示最新学期教师。
- 每位教师卡片在现有姓名和所属系下面增加一行紧凑学期文字：单学期显示 `2026年秋`，多学期显示 `2025年秋、2026年秋`。界面中不增加“任课”“任课学期”等前后缀。
- 教师按最近任课学期从新到旧排列；最近学期相同时按姓名排列。同一教师、同一课程、同一学期不得重复显示。
- 同一学期有多位教师时，每位教师各自显示一张卡片，不推断具体专业、班级或教学分工。
- 课程基本信息区域的结构、字段顺序和视觉布局保持不变，只更新现有“教材名称”字段的值。
- “教材名称”只取已知最新学期的教材，显示格式为 `教材名称（版次） · 出版社`；版次沿用来源表中的正式书名，不显示主编。
- 出版社缺失时只显示教材名称；来源明确标注“无”时显示“无指定教材”，不得用旧教材补成最新教材。
- 往期教材和任课记录继续保留在数据中，但课程基本信息不把多学期教材拼接成长文本。

## 教师详情页设计

### 页面路由

- 新增页面：`pages/teacher-detail/index`。
- 路由示例：`/pages/teacher-detail/index?id=<encoded-directoryId>`。
- 在 `app.json` 注册为普通页面，不加入底部 tabBar。
- 页面通过 `directoryId` 从本地教师目录解析教师；解析失败时显示“未找到教师”，并提供返回教师目录的操作。

### 页面信息结构

按以下顺序展示：

1. 教师头部：姓名、所属系、职称。
2. 教师点赞：当前点赞状态和点赞数，可点赞或取消。
3. 相关课程：列出本地课程资料中与该教师关联的课程。
4. 教师评价：评论输入、评论列表和删除操作。

本轮不展示导师资格，也不新增教师个人简介、头像、研究方向或外部资料抓取。

### 相关课程

- 复用现有 `getTeacherTeachingGroups()` 或抽取等价的本地查询函数，不请求新的后端资料接口。
- 每门课程显示课程名；已有可靠字段时可同时显示课程代码和适用专业。
- 课程项可点击进入现有课程详情页，并使用现有稳定课程 key。
- 每门相关课程同时显示该教师已知的学期，格式与课程详情教师卡片一致，只显示 `2026年秋` 这类文字。
- 没有关联课程时显示“暂无关联课程”。
- 不根据研究生导师资格推断本科授课关系。

### 教师互动

- 页面进入或重新显示时调用现有 `GET /api/v1/teachers/:teacherId/feedback`，其中 `:teacherId` 传 `directoryId`，读取点赞状态、点赞数和教师评论。
- 点赞与取消点赞复用现有教师互动接口。
- 未登录时点赞和评论均不可用，并沿用“请先进入测试身份”的提示。
- 已登录但未点赞时，教师评论输入区禁用，提示“点赞后可评价教师”。
- 点赞成功后立即开放评论；取消点赞后立即关闭新评论输入。
- 新评论发布成功后插入列表顶部，不额外请求评论者资料。

## 课程详情调整

- 课程基本信息区域不改版，只让“教材名称”使用最新学期教材和出版社。
- 底部教师区累计展示所有往期任课教师，并显示每位教师的任课学期；不得因导入新学期而删除旧教师。
- 课程评论输入区只以登录状态和提交状态作为可用条件，不再依赖 `hasLiked`。
- 删除前端“点赞后才能评论”的课程提示和判断。
- 服务端课程评论接口同步取消点赞前置校验，避免仅改前端后被服务端拒绝。
- 课程点赞、取消点赞、点赞数和现有课程评论数据保持不变。
- 课程详情底部教师卡片增加详情跳转；卡片内点赞按钮不触发跳转。

## 评论接口与数据设计

### 评论查询

仓储查询将课程或教师评论表与 `users` 表按 `user_id` 关联，实时读取 `users.nickname`。仍按 `created_at DESC` 返回。

评论展示对象增加：

```json
{
  "id": "comment-id",
  "content": "评论内容",
  "authorNickname": "当前昵称",
  "createdAt": "2026-07-28T04:03:00.000Z",
  "canDelete": false,
  "canModerate": false
}
```

- 创建评论的响应也必须返回 `authorNickname`，供页面即时插入。
- 不新增昵称快照字段，不需要数据库迁移。
- 修改昵称后，历史课程评论和教师评论都通过下一次查询显示新昵称。
- `anonymous: true` 等旧匿名语义不得继续误导前端；如保留兼容字段，也不能用于隐藏昵称。

### 点赞前置规则

- 服务端 `comment(targetType)` 逻辑必须按对象类型区分：
  - `course`：不检查是否点赞。
  - `teacher`：继续调用点赞关系检查，未点赞返回现有 `LIKE_REQUIRED` 错误。
- 不改变教师点赞数据结构和现有互动表。

## 个人页管理员联系入口

### 交互流程

在已绑定身份资料区域保留现有提示：

`身份资料如有误，请联系管理员更正`

交互分两级：

1. 保留当前标题和说明；点击整个提示区域后，只在其下方展开“联系管理员”按钮。
2. 点击“联系管理员”按钮后，打开居中的二维码弹窗。

再次点击提示区域可收起联系入口。弹窗可通过遮罩、关闭按钮关闭；点击弹窗内容本身不得关闭。

### 弹窗内容

## UI 与交互约束

- 延续现有小程序的 `surface`、间距、颜色、按钮和文字层级，不另建一套视觉语言。
- 教师详情页保持信息密度适中，不使用营销式大标题或装饰性卡片堆叠。
- 不在卡片中嵌套装饰卡片；教师基本信息、课程列表和评价区应是清晰的独立区段。
- 卡片可点击区域必须有按压反馈，点赞按钮必须保持独立稳定尺寸。
- 昵称和时间在窄屏允许换行，不能挤压或遮挡删除按钮。
- 评论正文保留自动换行，长昵称和长评论不得撑破容器。
- 空状态、加载状态、登录失效和接口错误沿用现有提示风格。
