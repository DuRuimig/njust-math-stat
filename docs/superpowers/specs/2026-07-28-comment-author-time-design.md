# 评论昵称与时间展示设计

> 状态：已被 `2026-07-28-teacher-comments-admin-contact-design.md` 取代。后者包含更新后的评论权限规则、教师详情页和管理员二维码入口，实施时以新设计为唯一依据。

## 目标

课程评论不再固定显示“用户”，而是显示评论者当前昵称，并将原始时间压缩为易读的“年月日 时:分”。用户修改昵称后，历史评论同步显示新昵称。

## 产品规则

- 每条评论依次显示当前昵称、评论时间和评论正文。
- 时间格式为 `YYYY年M月D日 HH:mm`，例如 `2026年7月28日 12:03`。
- 时间按查看者设备的本地时区格式化；无效或缺失时间不显示时间文本。
- 昵称来自用户当前资料，不保存发表评论时的昵称快照。
- 数据库中的默认昵称为“新同学”；接口遇到异常空昵称时同样回退为“新同学”。
- 只公开昵称，不公开真实姓名、学号、账号标识或用户内部 ID。
- 评论删除与管理员审核规则保持不变；课程和教师的评论发布权限以新规格为准，尤其课程评论不再要求先点赞。

## 服务端设计

### 评论查询

评论仓储查询将评论表与 `users` 表按 `user_id` 关联，同时读取 `users.nickname`。查询仍按 `created_at DESC` 返回。

评论接口新增字段：

```json
{
  "id": "comment-id",
  "content": "评论内容",
  "authorNickname": "当前昵称",
  "createdAt": "2026-07-28T04:03:00.000Z",
  "canDelete": false,
  "canModerate": false
}
```

`authorNickname` 是展示字段，不提供评论者资料查询入口。课程与教师评论共用同一后端逻辑，因此接口行为保持一致。

### 新评论响应

创建评论后，服务端同时返回当前用户昵称。小程序可立即插入新评论，不需要再次请求评论列表或用户资料。

## 小程序设计

- 新增独立时间格式化函数，将后端 ISO 时间转换为 `YYYY年M月D日 HH:mm`。
- 读取反馈与创建评论成功时，将 `authorNickname` 和格式化后的时间写入页面评论模型。
- 评论头部把固定“用户”替换为昵称；昵称缺失时显示“新同学”。
- 评论正文和删除按钮保持现有布局与交互。

## 数据流

1. 小程序请求课程或教师反馈。
2. 服务端查询评论并实时关联评论者当前昵称。
3. 服务端返回昵称、原始时间、正文和现有操作权限。
4. 小程序按设备本地时区格式化时间并渲染评论。
5. 用户修改昵称后，下次刷新评论时，历史评论显示新昵称。

## 错误与兼容

- 老评论无需迁移，因为评论表已有 `user_id`。
- 昵称为空时服务端和客户端均回退为“新同学”。
- 时间为空或不能解析时保留评论正文，时间位置留空，不显示 `Invalid Date`。
- 不改变现有数据库迁移、登录、评论删除或管理员权限逻辑；点赞与评论发布的关系以新规格为准。

## 测试与验收

- 仓储测试：评论查询关联用户昵称，仍保持倒序。
- API 测试：反馈和新评论响应返回 `authorNickname`，不泄露真实姓名、学号、账号标识或用户 ID。
- API 测试：修改昵称后，历史评论再次查询显示新昵称。
- 小程序测试：昵称渲染、空昵称回退、标准时间格式、无效时间降级、新评论即时插入。
- 回归门槛：全部 Vitest、`npm run check`、小程序 JS `node --check` 和 `git diff --check` 通过。
