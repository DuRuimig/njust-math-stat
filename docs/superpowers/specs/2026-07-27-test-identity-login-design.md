# 姓名学号测试身份设计

## 目标

先交付一个可在云端体验的非真实认证版本，让测试者用姓名和学号进入稳定账号，验证课程浏览、个人资料、点赞和匿名评论的完整流程。真实微信登录代码继续保留，但当前小程序入口隐藏，后续作为独立版本启用和联调。

## 产品边界

- 页面统一称为“测试身份”，明确提示“非真实认证；知道姓名和学号的人可能进入同一测试账号”。
- 测试身份只用于内部体验，不作为正式身份认证、学校账号认证或权限依据。
- AI 问答页维持本地演示状态；本阶段不接模型、RAG 或任何 AI API。
- 当前仍使用体验版 SQLite，不连接、配置或迁移真实 MySQL。
- 不提交、不推送、不部署；这些仍是后续独立确认的发布步骤。

## 方案

### 服务端

新增 `POST /api/v1/auth/test-identity`，请求体只接受：

```json
{
  "name": "测试姓名",
  "studentNumber": "123456789012"
}
```

- 路由只在 `ENABLE_TEST_IDENTITY_LOGIN=1` 时开放；关闭时返回 404，避免误当正式认证使用。
- 姓名去除首尾空白；学号去除首尾空白后必须是恰好 12 位数字（`/^\d{12}$/`）。
- 以规范化学号的 SHA-256 摘要生成 `test-identity:` 命名空间账号键，不把明文学号复制到 `account_id`。
- 首次进入时创建用户并保存姓名、学号；再次使用同一学号时回到同一用户。
- 已有学号对应的姓名与本次输入不一致时返回 `409 TEST_IDENTITY_MISMATCH`，不覆盖原资料，也不创建第二个账号。
- 成功后复用现有 7 天随机 Bearer 会话；数据库只保存 token 哈希。
- 并发首次进入复用现有 `findOrCreateUser` 竞争处理，最终只产生一个用户。

### 小程序

- 新增 `authMode: "test-identity"` 配置；后续切换到 `"wechat"` 时复用已完成的真实微信登录链路。
- 未登录的个人中心在测试模式显示姓名、学号输入框和“进入测试身份”按钮。
- 客户端调用 `loginWithTestIdentity`，先等待页面确认操作仍有效，再持久化会话，随后读取个人资料。
- 测试身份进入成功后，课程点赞、教师点赞、匿名评论和昵称修改继续使用现有 Bearer API。
- 微信登录按钮在测试模式隐藏；相关客户端和服务端代码不删除。

## 数据流

1. 用户输入姓名和学号。
2. 小程序调用 `/api/v1/auth/test-identity`，请求不携带旧 Bearer token。
3. 服务端检查测试开关、校验字段并按学号寻找或创建测试用户。
4. 服务端校验已有姓名是否一致，创建随机会话并返回 token。
5. 页面确认本次操作未被刷新或其他登录作废后保存 token。
6. 页面通过 `/api/v1/profile` 拉取身份资料，再开放点赞、评论和资料功能。

## 错误与并发

- 空姓名、非 12 位纯数字学号或多余字段：`400 VALIDATION_FAILED`。
- 测试开关关闭：`404 NOT_FOUND`。
- 同一学号姓名不一致：`409 TEST_IDENTITY_MISMATCH`。
- SQLite 或服务端异常：通用 `500 INTERNAL_ERROR`，不暴露数据库细节。
- 登录过程中页面刷新、会话变化或并发请求返回顺序变化：沿用现有 request epoch 与 `sessionSuperseded` 机制，旧结果不得覆盖当前身份或显示错误的重新登录提示。

## 测试与验收

- 后端接口：首次进入、重复进入同一账号、姓名不匹配、开关关闭、严格字段校验、并发首次进入。
- 客户端：请求体与无 Bearer 边界、延后持久化、存储失败、重复点击、迟到成功、旧会话响应作废。
- 页面：测试模式表单、成功进入、错误提示、busy 解除、微信入口隐藏。
- 回归：现有微信登录测试继续通过；生产环境开发测试会话仍保持关闭。
- 全量门槛：`npm run check`、全部 Vitest、全部小程序 JS `node --check`、`git diff --check`、敏感值扫描。

## 后续微信版

测试版稳定后，将 `authMode` 切到 `wechat`，单独完成 AppID/AppSecret 云端配置、Docker/云托管验证、微信开发者工具与真机登录测试。两种身份不自动合并；是否迁移测试数据需在正式启用前另行决定。
